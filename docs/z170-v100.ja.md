# z170: V100 2枚の個別運用

この手順は z170 固有の許可リストであり、一般の V100 向け設定ではない。ファン等の別用途にカードを交換した場合も、同じ index や同じ製品名だけで対象にしない。以下の UUID・モデル・PCI device ID の組以外はガードが拒否する。UUID を公開する前に確認する。

| 現在の index | UUID | name | pci.device_id |
|---|---|---|---|
| 0 | GPU-95283591-83a0-dfef-b9ff-e9e601e3d593 | Tesla V100-PCIE-32GB | 0x1DB610DE |
| 1 | GPU-450167d4-8564-727d-8a97-232f720b0d23 | Tesla PG500-216 | 0x1DF010DE |

index は現在の観測値で固定 ID ではない。実機の各 drop-in は GPU に UUID、NVSMI に /usr/local/sbin/z170-v100-nvidia-smi を指定する。unit 名は数字の index、デーモンは起動時に UUID を index に解決し、排他・状態マーカーも index 単位で扱う。各インスタンスは独立して監視・クランプする。

## ガードの範囲と限界

[ガードのソース](../z170_guard_nvidia_smi.py) は Python 3 と /usr/bin/nvidia-smi を使う。呼び出しごとに環境変数 GPU が許可 UUID と一致することを確認し、その UUID で index、UUID、name、pci.device_id を問い合わせて照合する。デーモンから渡された単一の -i / --id は現在の index または UUID と一致しなければ拒否し、一致すれば UUID に書き換えて実行する。対象が変わった index、複数・曖昧な selector、無指定操作は拒否する。例外はデーモンの UUID 解決に必要な特定の全 GPU index/UUID 一覧取得のみ。確認失敗は安全側に拒否するが、汎用的な nvidia-smi の権限制御やコマンドの完全な許可リストではない。直接の nvidia-smi 呼び出しや別サービスには効かない。照合と実行は原子的ではなく、長時間の監視中の構成変更にも対応しない。

index が入れ替わると稼働中のデーモンが持つ index と一致しなくなり、解除も拒否され得る。マーカーは UUID ではなく index に紐付くため、交換・再列挙前にジョブを退避しサービスを停止して解除結果とマーカーを確認する。失敗時は安易にマーカーを消したり別カードに -rgc したりせず、現在の UUID と実際のロック状態を確認して復旧する。

## インストールと設定

通常の [install.sh](../install.sh) はデーモンを /usr/local/sbin/nvidia-idle-clock、テンプレートを /etc/systemd/system/nvidia-idle-clock@.service に入れるが、ガードや drop-in は導入しない。通常のインストーラは全検出 GPU を対象にし得るため、このホストでは無指定で実行しない。既存のサービス・ジョブ・ロックを確認して保守時間に作業する。ガードは root が実行するためソースを検査し、インストール先と親ディレクトリを非特権ユーザーが書き換えられないようにする。

```bash
# リポジトリ内。現状を記録してから、信頼したソースを root 所有で設置
sudo install -o root -g root -m 0755 z170_guard_nvidia_smi.py /usr/local/sbin/z170-v100-nvidia-smi
```

以下の drop-in を先に作成する。例えば sudo systemctl edit nvidia-idle-clock@0.service と @1.service をそれぞれ実行する。通常の保存先は /etc/systemd/system/nvidia-idle-clock@0.service.d/override.conf と /etc/systemd/system/nvidia-idle-clock@1.service.d/override.conf。未導入の場合 systemctl edit の代わりに root 所有のディレクトリとファイルを作成できる。

```ini
# @0 の drop-in
[Service]
Environment=GPU=GPU-95283591-83a0-dfef-b9ff-e9e601e3d593
Environment=NVSMI=/usr/local/sbin/z170-v100-nvidia-smi
```

```ini
# @1 の drop-in
[Service]
Environment=GPU=GPU-450167d4-8564-727d-8a97-232f720b0d23
Environment=NVSMI=/usr/local/sbin/z170-v100-nvidia-smi
```

```bash
# 新規導入の場合のみ。上記ガードと drop-in を先に用意する
sudo ./install.sh 0 1
nvidia-smi --query-gpu=index,uuid,name,pci.device_id --format=csv,noheader,nounits
systemctl cat nvidia-idle-clock@0.service nvidia-idle-clock@1.service
systemctl show nvidia-idle-clock@0.service -p Environment
systemctl show nvidia-idle-clock@1.service -p Environment
systemctl status 'nvidia-idle-clock@*'
journalctl -u nvidia-idle-clock@0.service -u nvidia-idle-clock@1.service -b
```

インストーラはインスタンスを直ちに有効化・起動する。再起動すると停止処理と ExecStopPost がマーカーのある GPU のロック解除を試み、起動時も残存マーカーの解除を試みる。解除は以前のロックの復元ではなく driver 既定へのリセット。サービス停止・再起動、更新時の install.sh の try-restart は稼働ジョブの性能や他のロックに影響し得る。drop-in の変更は daemon-reload 後、各ユニットを安全な保守時間に個別 restart して反映する。エラーや解除失敗を journal で確認する。ガードの拒否は解除も止めるため、GPU を交換した後に安全に解除できるとは限らない。

交換後は旧カードが別用途（ファン用途を含む）でも新カードでも自動許可しない。まずサービス停止・解除を確認し、UUID / name / PCI ID を再確認した上で、管理者が対象・用途を選びガードの許可リストと drop-in をレビュー・更新し、モックテストと適切な実機検証を経て再開する。unit 名と実際の index が一致する保証はない。

## 検証の範囲

```bash
python3 -m unittest -v test_z170_guard_nvidia_smi
bash tests/run.sh
bash tests/installer/run.sh
```

[guard のテスト](../test_z170_guard_nvidia_smi.py) は問い合わせをモックする。UUID・モデル・PCI ID、index の不一致と selector の拒否を検証するが、systemd と本物の GPU を使う統合試験ではない。**このガード構成での 30 秒アイドル後のクランプと負荷発生時の解除・復帰は実機未検証**。既存の一般リファレンスにある過去の電力・レイテンシ実測を、この構成の検証結果と混同しない。共有 GPU で試さず、検証前に利用者と保守時間を調整する。
